# PDF Vectorization and Similarity Search Pipeline

A PDF document vectorization and semantic search pipeline built with **LangChain, LangGraph, Hugging Face embeddings, ChromaDB, and FastAPI**.

The system loads a PDF, splits it into overlapping text chunks, converts the chunks into vector embeddings using `sentence-transformers/all-MiniLM-L6-v2`, stores the embeddings in ChromaDB, and exposes a FastAPI endpoint for top-k similarity search.

The project intentionally does **not** use an LLM or a retrieval chain.

## Features

- PDF loading with `PyPDFLoader`
- Recursive text chunking
- Hugging Face sentence-transformer embeddings
- Persistent ChromaDB vector storage
- LangGraph ingestion workflow
- FastAPI similarity-search endpoint
- Configurable `top_k` search results
- Page-number metadata in search results
- Vector search score returned for each result
- Swagger/OpenAPI documentation through FastAPI


```bash

```

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Ingest a PDF

### Option 1: Standard ingestion

```bash
python ingest.py --file sample.pdf
```

This performs:

1. PDF loading
2. Text splitting
3. Embedding generation
4. ChromaDB storage

If an existing local `vectorstore/` directory is present, it is rebuilt to prevent duplicate chunks during repeated test runs.

### Option 2: LangGraph ingestion

```bash
python graph_ingest.py
```

This runs the same ingestion stages through a LangGraph workflow.

## Query the document

Use the Swagger UI or send a POST request to:

```text
POST /query
```

Example request:

```json
{
  "query": "What is the main topic of the document?",
  "top_k": 3
}
```

Example response structure:

```json
{
  "query": "What is the main topic of the document?",
  "top_k": 3,
  "results": [
    {
      "chunk_text": "Actual text returned from the PDF...",
      "page_number": 1,
      "score": 0.1234
    }
  ]
}
```

The exact `chunk_text`, page number, and score depend on the PDF and query. The score is a vector-store search score/distance and should not be interpreted as a percentage.

## Results file

`results.json` is reserved for recorded API results. It is intentionally initialized as an empty JSON array so that the repository does not contain fabricated search results.

After running the API, real responses can be recorded in this file, for example:

```json
[
  {
    "query": "What is the main topic of the document?",
    "top_k": 3,
    "results": [
      {
        "chunk_text": "Actual text from the PDF...",
        "page_number": 1,
        "score": 0.1234
      }
    ]
  }
]
```

## Important notes

- The embedding model is downloaded the first time it is used, so internet access may be required during the first run.
- The local `vectorstore/` directory is generated by the ingestion script and should not be committed to Git.
- Re-running `ingest.py` rebuilds the local vector database to avoid duplicate document chunks.
- This project performs vector similarity search only; it does not generate answers with an LLM.
